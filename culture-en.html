道 · Linux Culture

Understand the Linux universe, not just the commands.

Where Linux comes from, who created it, why a thousand “distributions” exist, how you install software and which certifications to take. The general background of the trade, on one page.

The creator

Linus Torvalds

In 1991, a 21-year-old Finnish student posted a now-famous message: “I'm doing a (free) operating system — just a hobby, won't be big and professional”. That hobby is the Linux kernel, today at the heart of the majority of the world's servers, of Android and of supercomputers.

He didn't just build a kernel: in 2005, to manage Linux's code, he created Git — the version-control tool you learn in chapter 17. Two foundational tools, one man.

His mascot? Tux, the penguin 🐧, chosen because Linus likes penguins. The kernel is free: anyone can read it, modify it, redistribute it (the GPL license).

Before (and around) Linus

The pioneers

Linux wasn't born from nothing: it stands on twenty years of ideas. Three or four names to know, and the dates that changed everything.

T·R

Thompson & Ritchie

Bell Labs · 1969–1972

They invented Unix, then the C language to write it. All of Linux's philosophy — small tools, “everything is a file”, the shell — comes from them.

RS

Richard Stallman

GNU project · 1983

Father of free software: he launched GNU, wrote the GPL license and major tools (Emacs, GCC). The “free” in Linux is his fight.

LT

Linus Torvalds

Linux kernel · 1991

He assembled the missing piece — the kernel — and released it freely. GNU + Linux = at last a complete system. Later, he created Git.

BF

Brian Fox

Bash · 1989

He wrote Bash, the shell you use in the Dojo — the default command interpreter of most distributions.

The basics to grasp

“Linux” is a kernel — not a complete system

The kernel alone isn't enough to use. A distribution (“distro”) wraps the kernel with tools, an installer, a desktop and a software manager. That's why there are hundreds of them.

Your apps — browser, web server, games…
The distribution — Ubuntu, Debian, Fedora, Arch… (tools + package manager + desktop)
The Linux kernel — the core: talks to the hardware (CPU, disk, network)
💻 The hardware

People often say “GNU/Linux”: Linus's kernel + the tools of Richard Stallman's GNU project (launched in 1983), which also gave us the free GPL license. Together, they form a complete operating system.

👉 Good news for you: the Dojo's commands (ls, cd, chmod, grep…) work identically on every distro. Only the way you install software changes.

Zoom in

Three distros everyone talks about

🟣 Kali Linux

The distro of ethical hackers and pentesters, published by OffSec. Based on Debian, it comes with 600+ security tools pre-installed (Nmap, Metasploit, Wireshark, Burp…). To be used in a legal and authorized context only.

🟠 Ubuntu

The best known to the general public. Published by Canonical, it brought Linux to the desktop for everyone and dominates on servers and the cloud. The LTS (Long Term Support) version = 5 years of updates, ideal for a server you keep.

🔵 Red Hat / RHEL

The reference in enterprise. You mainly pay for the support and the certifications. Many “Linux admin” job postings mention RHEL. Its free clones Rocky and AlmaLinux are identical, without the support.

🐧 Debian

The stable, 100% community-driven “grandfather” (since 1993). Nothing flashy, but legendary reliability — which is why so many other distros (Ubuntu included) are built on it.

Installing software

The package managers

On Linux, you don't install by downloading a .exe: you ask a package manager that fetches the software from an official repository, with its dependencies. Same gesture everywhere, a different command depending on the family.

Actionapt (Debian/Ubuntu)dnf (Fedora/RHEL)pacman (Arch)zypper (openSUSE)
Install packageapt install packagednf install packagepacman -S packagezypper install package
Searchapt search worddnf search wordpacman -Ss wordzypper search word
Update everythingapt update && apt upgradednf upgradepacman -Syuzypper update
Removeapt remove packagednf remove packagepacman -R packagezypper remove package

➕ There are also universal formats that work on (almost) every distro: Snap (Canonical), Flatpak and AppImage. Handy for desktop apps, a bit heavier. On the container side, Alpine uses apk, ultra-lightweight.

The recurring question

Why is it free — and who pays?

“Free” doesn't mean “worthless”. Free = you can read it, modify it, share it (it's a freedom). And most distros are also free of charge. So how does this whole world make a living? Simple: you don't sell the software — you sell the service around it.

🏢 Support & services

Red Hat (IBM), Canonical, SUSE sell enterprises assistance, warranty and long-term updates. The software is free; peace of mind isn't.

☁️ The cloud

AWS, Google, Microsoft run millions of Linux servers and sell you the computing power. Linux is the foundation of the entire cloud industry.

🤝 The giants who contribute

Google, Intel, Meta, Microsoft… pay developers to improve the kernel: they depend on it. The majority of the kernel's code comes from company employees.

🎓 Certs, training & donations

Certifications (Red Hat, LPI), training and donations to foundations (Linux Foundation, Debian) also fund the ecosystem.

🔁 The virtuous circle: everyone improves the same common good instead of reinventing the wheel in their own corner. The result: Linux often advances faster — and more solidly — than closed software.

Proving your level

The certifications that matter

Useful for landing a Linux admin or security role. Some are vendor-neutral (all distros), others tied to a vendor. The most respected are 100% hands-on: they sit you in front of a real server to fix.

CompTIA Linux+CompTIABeginnerFirst cert, vendor-neutral (all distros). A good starting point.

Did you know

A little glossary of geek culture

🐧 Tux

The mascot penguin, drawn by Larry Ewing in 1996. You see it at boot on many Linux machines.

⚖️ The GPL & free software

The license that guarantees a piece of software stays free: read, modify, share. The fuel of the whole ecosystem.

🔑 sudo

“Super User DO”: run a command with administrator rights. The famous sudo apt install….

📖 RTFM & man

“Read The Fine Manual”: before asking, read the manual. Hence man, the built-in docs you already know.

🏠 The shell & ~

The “~” denotes your home folder. A famous geek T-shirt: “there's no place like ~”.

🤓 “I use Arch, btw”

The cult joke: Arch users love to let you know. A badge of pride (and self-mockery).
